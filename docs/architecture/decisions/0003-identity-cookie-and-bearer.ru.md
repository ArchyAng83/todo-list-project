# ADR-0003: Identity cookie и bearer-only API

- **Статус:** принято
- **Дата:** 2026-11-08

## Контекст

Blazor UI нужна cookie-аутентификация. Внешним API-клиентам нужны токены. Смешивание cookie и bearer на одних и тех же endpoints создаёт CSRF и неоднозначность авторизации.

## Решение

Используем **ASP.NET Core Identity** с двумя раздельными путями доступа:

- Blazor использует **application cookie**.
- `/api/v1` принимает **только bearer-токены**, которые выдают Identity API endpoints.
- Blazor вызывает Application-сервисы напрямую и никогда не ходит в `/api/v1`.

## Последствия

- Чёткое разделение browser- и API-аутентификации.
- Нет CSRF-риска на API, потому что cookie там не принимаются.
- API-клиенты используют access и refresh токены со стандартными Identity-флоу.
- Две схемы аутентификации нужно явно настраивать; это покрыто integration-тестами.
- API становится чистым швом для будущих AI-tools и интеграций.
