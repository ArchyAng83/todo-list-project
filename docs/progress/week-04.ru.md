# Неделя 4 — тесты, контейнеры и observability

Даты: 2026-11-23 — 2026-11-29

Статус: код готов; образ собран, E2E-набор зелёный

## Цели

- Компонентные тесты на bUnit для списка задач, layout и переключателя языка.
- E2E-сценарии Playwright против реального процесса Kestrel и PostgreSQL.
- Воспроизводимый контейнерный образ веб-приложения.
- Health checks и структурированное логирование, пригодные для контейнерной платформы.
- CI, который запускает unit-, integration-, component- и E2E-тесты и собирает образ.

## Сделано

- Из страницы задач выделен презентационный компонент `TaskList` с состояниями загрузки, пустоты, ошибки, повтора и колбэками.
- 8 bUnit-тестов для `TaskList` и по 3 для `MainLayout` и `CultureSwitcher` (всего 14).
- Шов `ICurrentUserProvider`, чтобы компоненты получали `UserContext` без стека Identity в тестах.
- Проект Playwright E2E с фикстурой, которая поднимает контейнер PostgreSQL, веб-приложение на свободном порту и headless Chromium.
- 6 E2E-сценариев: вход с лендинга, вход демо-пользователем, быстрый ввод, поиск, представление Today и переключение на русский язык.
- Endpoint-ы `/health/live` (процесс) и `/health/ready` (база данных).
- JSON-логирование в консоль вне Development, со scopes и UTC-таймстампами.
- Многоступенчатый `Dockerfile`: публикация в Release, запуск от непривилегированного пользователя, порт 8080; `.dockerignore` не пускает в образ артефакты сборки и тесты.
- CI запускает component- и E2E-тесты и собирает контейнерный образ.

## Исправлено после E2E

- Razor считает строковый параметр компонента, записанный как `Error="_error"`, литеральным текстом; список задач навсегда оставался в состоянии ошибки. Теперь используется `Error="@_error"`.
- Blazor Server держит один DI-scope на circuit, поэтому layout и страница могли одновременно обращаться к PostgreSQL через один `DbContext`. `CurrentUserProvider` теперь резолвит `UserManager` в отдельном scope на вызов, а страницы уже получают сервисы Application через `IServiceScopeFactory`.
- E2E ждёт, пока Blazor навесит обработчики (маркер `_bl_*`), прежде чем кликать, чтобы клик не уходил в нативную отправку формы.

## Решения

- Компонентные тесты нацелены на презентационные компоненты с явными `EventCallback`, а не на страницы, которым нужны база и circuit.
- E2E запускает реальный процесс приложения, а не `WebApplicationFactory`: так проверяются static SSR, SignalR-circuit, cookie и статические файлы в том виде, в каком их видит браузер.
- Readiness-проба проверяет только PostgreSQL; liveness не зависит от базы, чтобы медленная база не перезапускала здоровый процесс.
- В образе используется встроенный JSON-логгер вместо дополнительного пакета логирования; коллектор читает stdout.
- В продакшене миграции остаются отдельным шагом деплоя; образ не применяет их при старте.
