- `CurrentUserProvider` явно возвращает `UserContext`; сервисы Application не читают неявное состояние.

- Страница проектов: создание, редактирование, переключатель архива, показ архивных, счётчики открытых и всех задач.
- Страница тегов: создание, редактирование, удаление, предпросмотр цвета, счётчик задач.
- Страница задач: быстрый ввод, поиск с задержкой, фильтры по статусу/проекту/тегу, сброс фильтров, переключение статуса, редактирование, удаление.

- Integration-тесты: изоляция и архивация проектов, счётчики задач в проектах, конфликт дубликата тега, обновление задачи с чек-листом и тегами, фильтры задач, 404 при доступе к чужим данным.

## Решения

- Разделение команд и запросов внутри Application; без MediatR, без generic-репозиториев, только ручной маппинг.
- Запросы используют `AsNoTracking` и проецируют сразу в DTO.
- Страницы и диалоги Blazor создают DI-скоуп на операцию через `IServiceScopeFactory`, поэтому scoped `DbContext` не живёт всё время жизни компонента.
- EF Core использует `QuerySplittingBehavior.SplitQuery`, чтобы избежать декартова взрыва при загрузке чек-листа и тегов задачи.
- Пункты чек-листа и связи задачи с тегами создаются через агрегат `TodoTask` и добавляются в контекст явно перед сохранением.
- Поиск использует `ToLower().Contains(...)`, потому что `EF.Functions.ILike` недоступен в Application.
- Доступ к чужим данным возвращает `not_found` (семантика 404) для любой операции сервиса.
