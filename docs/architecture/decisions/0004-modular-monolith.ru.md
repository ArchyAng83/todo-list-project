# ADR-0004: Модульный монолит без MediatR/AutoMapper

- **Статус:** принято
- **Дата:** 2026-11-08

## Контекст

Проект делается соло за 6–8 недель с сильным акцентом на читаемый и контролируемый код. Pipeline-heavy абстракции вроде MediatR и convention-based mapping добавляют indirection, который сложно оправдать для такого размера.

## Решение

Используем **модульный монолит** с четырьмя production-проектами и feature-oriented Application-сервисами. Команды и запросы — обычные методы сервисов. Маппинг ручной. Валидация — FluentValidation. Без MediatR, AutoMapper и generic repository layer.

## Последствия

- Путь выполнения явный и легко дебажится.
- Меньше сторонних зависимостей и никаких лицензионных сюрпризов.
- Больше кода маппинга, чем с AutoMapper; это осознанно.
- Application-сервисы могут разрастаться, поэтому делятся на команды (`TaskService`) и запросы (`TaskQueries`) по фичам.
- Одни и те же сервисы переиспользуются Blazor и API, поведение остаётся консистентным.
