# Неделя 8 — импорт/экспорт, покрытие E2E, доступность и v1.0

Даты: 2026-11-09

Статус: код завершён; все тесты проходят

## Цели

- JSON-импорт/экспорт с версионированной схемой и экспорт задач в CSV.
- Страница `/data` с загрузками из браузера, выбором файла и состояниями загрузки/ошибки/пусто.
- Конечные точки API `/api/v1/data` для экспорта и импорта.
- Полный проход E2E: экспорт, BOM в CSV, импорт JSON и слитые данные.
- Проверка доступности: ссылка «пропустить», главная разметка, локализованные подписи, стили для `focus-visible`.
- Релиз v1.0: версия, changelog, документация, тег и пуш.

## Готово

- `ExportDocument` (версия 1) содержит проекты, теги, задачи и вложенные пункты чек-листа со всеми настройками: заголовками, заметками, статусом, приоритетом, сроком (дата/время), смещением напоминания, повторением, проектом, порядком, тегами, пунктами чек-листа с завершённостью и метками времени.
- `TaskCsvExport.Build` формирует CSV: BOM в кодировке UTF-8, экранирование кавычек удвоением, CRLF-концовки, встроенные списки тегов и чек-листов, ISO-8601 даты и инвариантное форматирование.
- `DataTransferService` в Application экспортирует данные текущего пользователя и импортирует JSON-документ по слиянию:
  - проекты и теги переиспользуются по имени (регистронезависимо, с обрезкой пробелов), все задачи создаются как новые записи текущего пользователя, а идентификаторы из файла отображаются на существующие или новые;
  - отсутствие проекта/тега по ссылке в задаче — ошибка валидации, и ничего не сохраняется;
  - `CreatedAt` сбрасывается на момент импорта, `CompletedAt` следует за импортированным статусом;
  - для повторяющихся задач следующее повторение не генерируется; outbox напоминаний приводится в соответствие для каждой импортированной задачи;
  - неизвестная версия экспорта отклоняется, а неудачный импорт атомарен.
- Страница `/data` с кнопками экспорта в JSON/CSV, выбором только JSON-файла, индикатором импорта, областью результата с `aria-live`, состояниями загрузки/ошибки/пусто и сводкой по проекту/тегам/задачам на пользователя.
- Хелпер `data.js` для загрузок через Blob с подсказанным именем файла.
- Конечные точки API `/api/v1/data`: `GET /export` (версионированный JSON), `GET /export/csv`, `POST /import` (возвращает `ImportSummary`); все требуют bearer-токен и ограничивают данные пользователем.
- Unit-тесты для экранирования CSV, BOM/CRLF, форматов дат/времени, рендеринга перечислений и версии схемы; интеграционные — для кругового импорта, переиспользования по имени, ограничения по владельцу, проверки версии и внешних ключей, отсутствия следующего повторения после импорта; E2E-путешествия для скачивания JSON/CSV и импорта файла с проверкой появления задачи в списке.
- Улучшения доступности: ссылка «перейти к содержимому» на главную разметку, `id="main-content"` у области страницы, локализованная подпись меню и `aria-label` навигации, стили `:focus-visible`, область `aria-live="polite"` для результата импорта.
- RU/EN-ключи ресурса для страницы, кнопок, подсказок, сообщений валидации и сводки импорта.
- Сборка: без предупреждений и ошибок в Debug и Release.
- Тесты: 52 unit, 57 integration, 32 component, 14 E2E (155 всего). Дымовая проверка: демо-пользователь экспортирует JSON, где корень имеет `version: 1`, скачивает CSV с корректным BOM, импортирует его через выбор файла и видит задачу в списке на английском и русском.

## Решения

- Экспорт версионируется явным полем `Version` при `CurrentVersion = 1`. Эволюция схемы остаётся безопасной, потому что импортер отклоняет неизвестные версии, а не угадывает.
- Слияние повторно использует проекты и теги по имени, а не по ID. Столкновение ID между пользователями было бы сюрпризом для переносимой резервной копии, а столкновение имён — тем, что человек ожидает при восстановлении своего файла.
- Пункты чек-листа создаются заново (только заголовки) в импортированном порядке с обнулённой завершённостью. Новый должен быть действующим, а сырые ID привязали бы пользователя к чужому экспорту.
- Remind outbox приводится в соответствие даже для задач без напоминаний — без запроса БД это проще согласовать с `TaskReminderScheduler`, а не дублировать расчёт времени. Завершённые задачи не создают следующего повторения и не добавляют напоминание.
- JSON экспортируется отформатированным с перечислениями в виде имён, чтобы человек мог его просмотреть; CSV сделан плоским для таблиц.

## Исправлено после тестов

- В `TodoTask.CreateNextOccurrence` было неформатированное тело одной строкой; приведено к обычному блоку.
- Hелпер E2E `WaitForBlazorAsync` объединён в общий метод для страницы данных, а не повторяет селектор `button[type=submit]`, потому что на странице экспорта кнопки загрузки, а не отправки формы.

## Follow-up: подготовка деплоя в v1.0.1

- Репозиторий готов к деплою без хоста и SMTP-аккаунта: ключи Data Protection сохраняются на volume, forwarded headers включаются явно со списком доверия, auth- и antiforgery-cookie безопасны вне Development, а при старте выводятся предупреждения о несохранённом key ring или отсутствующем SMTP-хосте.
- `Dockerfile.migrations` и `docker-compose.production.yml` упаковывают шаг схемы и runtime-стек; `.env.production.example` описывает конфигурацию, а ADR 0006 фиксирует форму деплоя.
- Полный набор теперь 172 теста (54 unit / 72 integration / 32 component / 14 E2E).

## Follow-up: v1.0.2 — эксплуатация, безопасность и claim напоминаний

- Dispatcher напоминаний берёт PostgreSQL session advisory lock перед выборкой due-строк, поэтому несколько реплик не отправляют дубли; ADR 0007 фиксирует решение. `ReminderRetentionWorker` удаляет терминальные напоминания после `Reminders:RetentionDays`.
- Security hardening: CSP и browser hardening-заголовки, `AllowedHosts` с предупреждением в production, `ValidateOnStart` для опций email/reminders, read-only контейнер со сброшенными capabilities и лимитами ресурсов.
- Runbook'и и скрипты эксплуатации: `backup-postgres.ps1` копирует базу и ключи Data Protection, `restore-postgres.ps1` восстанавливает в черновую базу, `smoke-test.ps1` проверяет health, логин, задачу, board, calendar и экспорт. Восстановление прогнано на реальном контейнере PostgreSQL.
- CI: проверка уязвимых пакетов, CodeQL, Trivy-сканы обоих образов, Dependabot и smoke-тест на одноразовом compose-стеке после сборки образов.
- Полный набор теперь 176 тестов (54 unit / 76 integration / 32 component / 14 E2E), сборка Release без предупреждений.
